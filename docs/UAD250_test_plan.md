# UAD EMT 250 plugin: headless capture and test plan

*Status (25 October 2026): harness built; full capture run done (464 cases + 40 extra B_ghost cases, in `analysis/uad250/captures/`, gitignored); A1 structure, B1/B2 level, C1/C2/C3 modulation analysed (§2). Analysis scripts: `tools/uad250/analyze_{a1,b1,c1,c2,c2b}.py`.*

**Why.** `docs/EMT250_program.md` §4 and `NEXT_STEPS.md` §10: the Altiverb REV-250 presets are single frozen captures, so the 250 program's modulation, level behaviour and parameter-change behaviour cannot be read from them. The UAD EMT 250 is a software emulation we can drive with any stimulus and any parameter state, so it is a **test bench** for (a) detectors (known-modulated reverb), (b) a *prior* for what the E program's modulation and non-linearities look like, and (c) a broad cross-check of the static structure (loop lengths, early taps, band RTs). It is **not** the emulation target: the target is still the 246's Program E (`EMT250_program.md` scope). Claim labels below follow the project convention (C / S / H).

## 1. How the capture works (no DAW)

`tools/uad250/au_render.swift` hosts the AU **in-process** with `AVAudioEngine` in offline manual-rendering mode: a source node feeds the file, the plugin renders, the result is written as 32-bit float WAV. Parameters are set by name (`--set Time="2.5 s"`) and can change **mid-render on a sample boundary** (`--auto events.json`: `{t, param, value}` or `{t, action: "reset"}`); blocks are split at event times.

What was learned getting it to work (all **C**, measured here):
- **Out-of-process hosting (`.loadOutOfProcess`) does not work**: the sandboxed host cannot reach the UAD driver and the plugin returns only a constant −98 dBFS noise floor, ignoring input and parameters. In-process works.
- Calling the AU render block directly fails with −50 in-process; the engine route works. The plugin segfaults in its atexit handlers, so the host ends with `_exit(0)` after the file is closed.
- It runs the **UAD-2 DSP path** (log: "UAD2 mode", Apollo Twin X / UAD-2 Satellite present). Reported latency is **523 samples at 48 kHz**; every IR carries it (measure it per rate, do not assume it).
- **Renders are faster than real time** (a 30 s file takes about a second), so the full suite is minutes, not hours.
- **Bit-identical repeatability across fresh instances**, with modulation both on and off (null −300 dB over 0–4 s). The plugin's randomness is a seeded generator that restarts the same way each load.
- **WetSolo = 1 forces 100 % wet whatever Mix says.** Mix-law and dry-path cases therefore set WetSolo = 0.
- Parameters (15): Program (Reverb / Delay / Phase / Chorus / Echo / Space), Time (16 steps 0.4–4.5 s), LFDecay (×0.5 / 1 / 1.5 / 2), HFDecay (×0.25 / 0.33 / 0.50 / max), LDelayTime and RDelayTime (0–315 ms in 5 ms steps), Phase (16 steps to 15 ms), ChorusMode (I–IV), Echo (0–315 ms), Predelay (0 / 20 / 40 / 60 ms), Outputs (Rear / Front), Mix, WetSolo, Noise, Power.
- **Noise is an additive output noise floor, not a modulation switch** (silence: −128 dBFS rms off, −94 dBFS rms on; the "Noise on vs off decorrelates by 2–4 s" seen at bring-up is that floor overtaking the decaying tail). **Corrected 25 October 2026; an earlier version of this note called it the modulation switch.** The algorithm's modulation is always on (§2).

Run it: `.venv/bin/python tools/uad250/uad250_suite.py build | list | run [--only 'C_mod/*'] [--smoke]`. One process at a time under `tools/memguard.py`; finished cases are skipped, so a run can be stopped and resumed.

## 2. Scope (user, 25 October 2026) and results

**Scope.** We look for modulation and non-linearity **in the algorithm**, not in the 250 unit or the plugin's modelling of its hardware: the 246 only runs the algorithm on its own hardware. So plugin-side behaviour that is converter, DSP or analogue (listed under "hardware-side, set aside") is out of scope, and a result counts only if it is a property of the reverb arithmetic or structure. Calibration for level tests: **0 VU = −18 dBFS RMS** (user, unit calibration); the level ladders and `cal_*` cases are centred on that.

### 2.1 Static structure (A1, 256 settings, Noise off) — `analysis/uad250/a1/a1.csv`  **[S]**
- **Early taps (R): 0 / 16.27 / 27.27 ms, gains 1.00 / 0.71 / 0.58, identical at all 256 settings** (RT, LF and HF independent). Altiverb REV-250: 0 / 16.31 / 27.27, 1.00 / 0.71 / 0.59. **L carries the same taps 11.87 ms later** (Altiverb 11.92). Agrees with `EMT250_program.md` §2.
- **RT(1 kHz) = the label** (e.g. 4.42 s at 4.5, 2.52 at 2.5). Octave T60 at Time 2.5: LF ×0.5 / 1 / 1.5 / 2 gives 125 Hz 1.24 / 2.39 / 3.79 / 4.91 s (×0.52 / 1 / 1.59 / 2.05) with 4 kHz and 8 kHz unmoved (±0.03); HF ×0.25 / 0.33 / 0.50 / max gives 8 kHz 0.63 / 0.91 / 1.35 / 1.98 s (4 kHz 0.99 / 1.44 / 1.91 / 2.31) with 125 Hz unmoved. The LF multiplier acts on the low band only and the HF multiplier on the high band only, around a flat mid; the base shape at LF ×1 / HF 0.50 is the 250's own LF/HF balance (compare `EMT250_program.md` §1).
- **Loops: 167.42 / 190.00 / 210.25 ms**, RT-independent (found at RT ≥ 2.5; the 190 / 210 ms loops clear the 8σ test at only 10 of 256 settings, 167.42 at 39+). Altiverb REV-250: 167.98 / 190.12 / 210.52. The plugin's three lengths are **integers at 24,000 Hz: 4018 / 4560 / 5046 samples** (within 0.1 sample), unlike Altiverb's 4430 / 5014 / 5552 at 26,373.6 Hz; the two sets differ by −0.33 / −0.06 / −0.13 %, which a single clock ratio does not explain. **Read-out:** the plugin is a real-250 (24 kHz) implementation of the same three-comb design, the Altiverb E-program loops are a different length set. The 246-E is still the target; this is a structure prior. **[S for the plugin; the comparison H]**

### 2.2 Modulation (C1, C2, C3): the algorithm is strongly time-varying, always on  **[S]**
- **Steady tones come back modulated.** A static reverb returns a pure tone. At 0 VU through Time 2.5 the carrier keeps **82 % (250 Hz), 52–58 % (1 kHz), 45 % (4 kHz L)** of the power; the rest is sidebands. Sideband share grows with frequency, as delay (FM) modulation does and gain (AM) modulation does not. Amplitude varies by 22 % rms (250 Hz) to 43–47 % (1, 4 kHz).
- **Modulation bandwidth scales with the tone frequency:** half the sideband power lies within |ν| < 0.7 / 3.3 / 12.9 Hz at 250 Hz / 1 kHz / 4 kHz, i.e. **ν ≈ 0.0028–0.0033 · f**; 99 % within 3.3 / 20 / 56 Hz. That is a slowly drifting delay (a continuous delay change of about 3 ms per second, equivalently a fractional pitch shift of about ±0.3 % per loop pass), not a sinusoid at one fixed rate (the 250 Hz lines are at 0.54 / 0.56 / 0.73 Hz, one rate would give a line at fixed ν for every f).
- **Independent of Time** (1 kHz at 0.4 / 2.5 / 4.5: sideband bandwidth 3.3 Hz, carrier 37–74 % / 52 % / 54 %) **and of level** (0 VU −15 dBFS peak tone identical to −20 dBFS).
- **The random state is a function of absolute stream time, and the early taps are not part of it.** In every snapshot the first 30 ms (direct path and 3 early taps) null to −55 dB; after that, impulses ≥ 0.5 s apart are uncorrelated (ρ ≈ 0 at 0.5 / 1 / 2 / 3.7 s). Correlation with the reference falls smoothly with the onset offset: ρ(0.1–0.5 s window) 1.00 (≤ 100 samples), 0.85 (≈ 10 ms), 0.71 (≈ 21 ms), ≈ 0 (≥ 0.5 s). Twelve seconds apart the reverb is partly correlated (ρ ≈ 0.3, all bands, all RT; the early taps repeat exactly), so the modulation has a long-period component that returns near multiples of 12 s: not yet identified. A fresh instance repeats a render bit-exactly; `reset` mid-stream does **not** re-seed it (the second impulse correlates 0.37 with the first). Consequence for the 246: single captures of one setting are *independent realisations* of the same process, as the M/L pairs were.
- **Period, split and depth: see §2.4** (dense sampling answered the open items from the 12 s train).

### 2.4 Dense sampling (C_dense): period, split and depth  **[S for period and apparent depth; H for the per-loop split]**
Method: the response h(t_onset, τ) sampled every 0.25 s over 240 s at Time 0.4 (1 s trains at four 0.25 s offsets, tails do not overlap; `analyze_dense.py`). Per snapshot, the delay shift of a lag window is found by cross-correlating the 60–300 Hz band against an iterated template.
- **The modulation is a near-sinusoid of period 1.807 s (0.554 Hz).** The shift series has H2 and H3 below 0.013 ms against H1 of 0.15–0.42 ms; pair coherence at 250 Hz versus onset separation is minimal at 0.75–0.9 s (0.04–0.08) and recovers at 1.8 s (0.65), 3.6 s (0.56), 5.4 s (0.64) and 9.0 s (0.55), i.e. at multiples of 1.80 s. It is **not** gain modulation (the early taps, 0–30 ms, never move) and it is the same in L and R.
- **It is not a single clean sinusoid.** The fundamental has sidebands about 0.009 Hz away (a slow drift of its amplitude or phase on a ~100 s scale; 0.529 / 0.545 / 0.554 / 0.560 / 0.568 Hz), so recovery at the period is partial (0.5–0.65, not 1), and a second line at 0.74–0.75 Hz shows in the later lag window (160–260 ms, R: 0.134 ms).
- **Several modulators (the "one per loop" reading here was revised by §2.5: the 0.55 Hz line is common to all loops).** The 250 Hz tone sidebands (`analyze_c2b` data, ν resolution 0.018 Hz) show lines at ±0.549 / 0.552 Hz (strongest), ±0.730 Hz, ±0.67 Hz, and 1.10 Hz (= 2 × 0.55); the 0.73 / 0.55 ratio is 4/3. Three loops (167.42 / 190.00 / 210.25 ms) and three lines (≈ 0.55 / 0.67 / 0.73 Hz) suggest one low-rate modulator per comb, with the assignment unproven (the lag windows mix all three loops' paths). The shifts in the 40–80, 80–160 and 160–260 ms windows correlate only +0.5…+0.9 (R) and +0.6…+0.9 (L): partly common, not one global modulator.
- **Depth: about ±0.4 ms (≈ ±10–11 device samples at 26,373.6 Hz; ±9.5 at 24 kHz).** Cross-correlation gives H1 = 0.42 ms (R, 80–160 ms), 0.32–0.33 ms (L, 80–260 ms); the J0 fit to the anti-phase coherence at 250 Hz gives 0.395 ms. The 125 Hz fit (0.86 ms) is biased by the static low-frequency part, and ≥ 500 Hz is floored by the static fraction (ρ → 0.16 at 1–2 kHz whatever the separation), so those do not constrain depth. For a ~4400-sample loop this is ±0.24 %, a peak rate of change 2π · 0.554 · 0.4 ms = 1.4 × 10⁻³, the same order as the tone sidebands' ν ≈ 0.003 · f once two passes are counted.
- **Static fraction.** About 16–22 % of the response energy after 40 ms is unmodulated (coherence floor at ≥ 1 kHz; the early taps are static and the 125 Hz band keeps 0.5–0.8).
- **Against the 246:** M/L's rotation is 0.83 Hz with 0.15 rad rms (`ml_structure.md` §9); this plugin's rates (0.55 / 0.67 / 0.73 Hz, delay depth ±10 samples) are a different mechanism and different numbers. Whether the 246's Program E follows the plugin or the M/L rotation is still the open question of `EMT250_program.md` §8; the E's own AMPL pairs decide it. The method here (onset-sampled delay shifts, coherence recovering at the period) can be run on any library pair set with enough repeats.
- **Limits:** the shift estimator sees the apparent shift of a mixture of paths, so the amplitudes are lower bounds on a single loop's delay swing; periods are better determined than depths. Time 2.5 at 3 s spacing was captured (`dense_T2.5_sp3_*`) but not analysed (it aliases a 0.55 Hz line at 0.33 Hz sampling and needs the period known; use it to test whether the lines move with Time).

### 2.5 Per-loop attribution (C_loops: 240 s of 0 VU white noise, Time 4.5, two seeds)  **[S for the common 0.552 Hz line; H for the rest]**
Method (`analyze_loops2.py`): the output correlates with itself at each loop's lag (167.42 / 190.00 / 210.25 ms), so for each loop the correlation ρ(lag, t) in 0.5 s windows is computed; the loop's delay is modelled as L_j + A sin(2π f t + φ) in absolute stream time and (A, φ) searched per trial f to maximise the summed ρ. Direct peak picking was tried first and rejected (wrong-lag outliers, no agreement between seeds). Validation: two different noise seeds must give the same line spectra and phases, because the delay is a function of time, not of the input: the line spectra correlate +0.5…+0.6 across seeds for every loop and channel, and the fitted 0.552 Hz phases agree to the grid (180° in 11 of 12 fits in the 200–800 Hz band).
- **0.552 Hz (period 1.81 s) is common to all three loops, at the same phase** (sin(2π · 0.552 · t + 180°) from stream start), in both channels and both seeds. So it is a shared modulator (a common delay/read position), not one per loop. Amplitude (200–800 Hz band): loop 167 0.15 ms; loop 190 0.18–0.21 ms (R) and 0.43 ms (L); loop 210 0.21 ms (R) and 0.46–0.49 ms (L). The 100–400 Hz band gives about 0.08–0.18 ms for the same lines, so the amplitudes are uncertain by a factor 2–3 and are lower bounds on the swing (the correlation profile smears); the dense-sampling value of ±0.4 ms (§2.4) is consistent with the upper end.
- **A second line near 0.74 Hz belongs mainly to the 210 ms loop** (R: 0.15–0.21 ms with the same phase, 225°, in both seeds at 0.740 Hz; L similar, amplitudes 0.15–0.49 ms depending on band and grid), and is weak on the 190 and 167 ms loops (0.05–0.08 ms). The tone sidebands (§2.4) found this line at 0.730 Hz, the dense lag windows at 0.74–0.755 Hz: the frequency is 0.73–0.755 Hz, not pinned to better than ±0.01.
- **The 0.67 Hz line seen in the tone sidebands is not confirmed** by the loop fits (no separate peak above the floor).
- **Read-out (H):** a global modulator at 0.552 Hz moving all the loops together, plus a private one at ≈ 0.74 Hz on the longest loop; the 167 ms loop shows only the common line. The L channel's swing is about twice the R channel's for the long loops.
- **Limits:** the per-loop gains are small (≤ 0.02 in mean ρ units against a peak ρ of 0.15–0.22), so amplitudes and the weak lines are marginal; the longer-lag, higher-band version of the estimator fails because the shifts exceed the width of a high-band correlation peak. Times 2.5 and 1.5 were captured (`C_loops/noise240s_T2.5_seed11`, `T1.5`) but give no usable loop peaks above the floor (loop ACF peaks are below the detector at those RTs).

### 2.6 Against the Altiverb REV-250 presets (`tools/uad250/compare_altiverb.py`)
- **Early structure matches, with inverted polarity.** The first taps correlate |0.89| (R) and |0.92| (L) within 1 sample, with the plugin's sign opposite to the Altiverb deconvolution; tap spacing 0 / 16.35 ms (plugin) versus 0 / 16.44 ms (Altiverb), a 4-sample difference at 48 kHz; R leads L by 11.87 ms (plugin) versus 11.94 ms (Altiverb). Over 45 ms the correlation falls to |0.63| (the diffuse start is a different realisation). Which polarity is right for the 246 is open (deconvolution conventions); do not carry the plugin's sign across.
- **Decay: the presets sit at plugin LF ×1.5 with HF between ×0.50 and max.** Fitting each preset's octave T60 (both channels) to the plugin grid at the same Time gives LF ×1.5 for 8 of 9 presets and HF 0.50 or max, rms log error 0.07–0.12. Ratios at RT 4.5: Altiverb RT125 / RT1k = 1.47, RT8k / RT1k = 0.66; plugin LF ×1.5 gives 1.44 and HF ×0.50 / max give 0.54 / 0.79. So the presets use LF/HF decays that the plugin's four discrete HF steps straddle: the preset HF is about 0.66 in these units. This is the same "not neutral" balance as `EMT250_program.md` §1.
- **Spectrum:** relative to 250 Hz the plugin's cluster is brighter at 8 kHz by +5.2 dB (R) and +1.2 dB (L) than the Altiverb, the dark-chain difference of `EMT250_program.md` §5.
- **Loops:** plugin 167.42 / 190.00 / 210.25 ms versus the Altiverb 167.98 / 190.12 / 210.52 ms (doc §3 values; this script's own detector found no loops in the Altiverb caches at 6σ).
- **So the plugin can serve as a structure and modulation prior (taps, three loops, LF/HF law, early/late split) but cannot null the Altiverb tails; the two differ in loop lengths by 0.06–0.33 %, a few samples of tap timing, and chain brightness.**

### 2.7 Can the library test the E program's modulation? (checked 25 October 2026)
- **No repeats exist for the E program.** The Tomkin set holds S, M, L and Non-Lin only (AMPL pairs exist for S, M and L, none for E). The Altiverb set has one capture per REV-250 setting (nine RT steps and an unlabelled short one). So the onset-sampled delay-shift and coherence-recovery analysis of §2.4 cannot be run on the E; nothing in the library gives a second realisation of any REV-250 setting, and there is no hardware route (project rule).
- **What the M/L pairs say about mechanism.** M and L decorrelate between captures *flat across frequency* (`ml_structure.md` §4, §9: the coupling rotation, 0.83 Hz, 0.15 rad rms). The plugin's modulation is the opposite kind: delay-type, LF coherent and HF decorrelated (§2.2, §2.4: sidebands and decorrelation grow with frequency). The two mechanisms are distinguishable by the band dependence alone.
- **Indirect test on single captures (`comb_coherence.py`, Time 4.5).** The comb coherence of the decay-flattened tail at k × 168 ms (k = 1…8), per octave band, was measured on the Altiverb REV-250 4.5 s capture, on the plugin's impulse snapshots (no sweep smear) and on the plugin through 5 / 10 / 20 / 30 s sweeps deconvolved like a library capture.
  - **Altiverb:** ρ(k = 1 → 8) = 0.15 → 0.10 at 1 kHz, 0.17 → 0.08 at 2 kHz, 0.17 → 0.02 at 4 kHz, 0.30 → 0.08 at 250 Hz (R; L similar). The k = 8 / k = 1 ratio falls with frequency above 1 kHz (0.67, 0.47, 0.12 at 1 / 2 / 4 kHz), the direction delay modulation predicts and a flat rotation does not. **[H]**
  - **Plugin through a 20–30 s sweep** has the same shape at 4 kHz (0.11 → 0.01 and 0.06 → 0.00), and the plugin's 4 kHz coherence depends strongly on sweep length (k = 8: 0.09 / 0.09 / 0.01 / 0.00 for 5 / 10 / 20 / 30 s), as a modulation of period 1.8 s smearing the sweep would. The Altiverb sweep length is unknown, so only the shape, not the level, can be compared.
  - **Mismatch:** the plugin's 0.5–2 kHz coherence is 3–10× lower than the Altiverb's at every sweep length and in the impulse snapshots (e.g. 1 kHz: 0.02–0.05 against 0.10–0.15, flat to k = 8 in the Altiverb). The plugin's loops decohere by k = 2 in those bands while the Altiverb's stay coherent over 8 passes (1.3 s). So the E program is **not** modulated as strongly as the plugin in the mid bands (or has a different loop/tap structure there), even if its HF behaviour looks delay-like.
  - **Caveats:** the sweep deconvolution leaves a plateau of ρ ≈ 0.1 across k in some bands (plugin 5 / 10 s sweeps at 2 and 4 kHz), so absolute coherence from a sweep capture is unreliable; the ACF noise sd is 0.02–0.1 depending on band; one capture of each.
- **Read-out:** the E is more likely a delay-type (250-style) modulation, weaker in the mid bands than the plugin, than M/L's flat rotation **[H, weak]**. The plugin's period (1.81 s), rates (0.552 Hz common, 0.74 Hz on the longest loop) and depth (±0.4 ms) are an upper-end prior for the E. Settling it would need E repeat captures, which cannot be made here; the open item stays in `EMT250_program.md` §8.

### 2.3 Non-linearity (B1, B2): the algorithm arithmetic looks high-resolution  **[S]**
- **No visible word-length or overflow effect from −60 to −18 dBFS.** After subtracting the plugin's fixed start-up response (see hardware-side below), impulse responses at −18 … −60 dBFS scaled to equal input agree with the −30 dB reference to −120 … −133 dB (early) and to −100 … −115 dB (tail, Time 4.5). Even −90 dBFS inputs (signal at −108 dBFS) stay within −51 … −80 dB of their linear prediction, i.e. an absolute error near −160 dBFS. A 16-bit loop would show truncation noise near −96 dBFS and a tail dead zone; neither exists. **So the plugin does not emulate the 250's fixed-point word length and cannot tell us the 246's quantisation or limit-cycle behaviour**; that stays an open item for the 246 evidence (the library's deep tails).
- **Continuous signals at and above the 0 VU reference are linear.** Noise at −36 … −18 dB RMS (peaks to −3 dBFS): scaled outputs agree to −69.7 dB (a floor common to all levels); sines at −60 … −3 dBFS peak: no level-dependent harmonics (H2…H5 ≤ −90 dB re fundamental, constant with level).
- **Hardware-side behaviours, set aside (measured, not algorithm):** (i) a **start-up ghost**: a fixed response of about −100 dBFS (as if an input of ≈ −57 dBFS arrived at stream start), identical for every level, polarity and an all-zero input, bit-identical per run; subtract the `B_ghost/zero_input_T*` capture at the matching setting before any low-level analysis; (ii) **soft overload above 0 dBFS** (+6 dBFS peak sine: 4 dB compression, H3 at −9 dB at 1 kHz; impulses +6 / +12 dBFS: peak −2.7 / −8.2 dB); (iii) a **switch near −14.5 dBFS on a single impulse** (clean to −15, then a residual near −41 dB, mostly below 200 Hz, with the same size at higher levels): looks like a DSP block-scaling change, not a continuous non-linearity, and noise at −18 dB RMS does not show it; (iv) **523-sample latency** and the Noise-switch floor (−94 dBFS rms).

## 3. The tests

*Reading note (25 October 2026): "Noise on/off" in the cases below turned out to be an output noise floor (§1), so those pairs are duplicates above −94 dBFS and carry no modulation information; the modulation tests stand on the Noise-off renders. The D_programs group (Chorus, Space, Delay, Echo, Phase) is **confirmation only**, to check how the unit's programs relate to the reverb algorithm; the priorities are structure (A), algorithm non-linearity (B) and modulation (C).*

Groups, case counts and audio length from `uad250_suite.py list` (447 cases, about 107 min of audio). Inputs are mono, fed to L and R identically unless stated.

### A. Static structure, Noise off (260 cases): the algorithm, broadly
- **A1** an impulse at every one of the 16 Time × 4 LF × 4 HF settings (256). Gives per-band T60 (RT, LF/HF multipliers), the loop lengths by the harness's decay-flattened ACF, the early taps, the L/R onset offset, and how each loop's feedback gain and loop filter move with the controls. Directly comparable with `EMT250_program.md` §1–§3 (167.98 / 190.12 / 210.52 ms loops, 3 early taps at 0 / 16.31 / 27.27 ms, R before L by 11.92 ms) and with the 246 E model fit.
- **A2** log sweeps (ESS, 20 Hz–20 kHz, −12 dBFS) at four Times: the same IR with ~40 dB more SNR than an impulse, plus a linearity cross-check against A1.
- Questions it answers: do the plugin's three loops match 4430 / 5014 / 5552 device samples, or the real 250's (≈ 24 kHz)? Is the early-tap gain fixed in RT (Altiverb says yes; the patent says no)? What is the LF/HF decay law versus the 246 S/M/L law? Is the loop count/length RT-dependent?

### B. Non-linear and level behaviour (62 cases): *the main target, part 1*
- **B1 impulse ladder**, +12 … −90 dBFS in 6 dB steps at Time 0.4 and 4.5, Noise off. Normalise each IR by its input gain and compare: any residual is non-linearity. Reads input clipping/saturation (the +12 and +6 dBFS cases), internal overflow, **quantisation / truncation noise in the loops** (the tail floor versus level), and a **dead zone or limit cycles** in very quiet tails (does the decay reach the floor or stall or hold a pattern). The 246's own 16-bit word length is the question this informs.
- **B2 sine ladder**, 250 Hz / 1 kHz / 4 kHz at −60 … +6 dBFS, Time 0.4, Noise off: steady-state harmonic content versus level (THD and its level slope), plus a two-tone (1000 + 1100 Hz) intermodulation case.
- **B3 floor**: silence for 20 s at Noise 0/1 × Power on/off (idle noise, dither, spectrum, any idle tones), and white noise through Power off (bypass path) and Mix 0 (dry path) for the converter/analogue chain's bandwidth and gain.
- Caution: float inputs above 0 dBFS may be clipped by the host/driver rather than the plugin; compare the +12 / +6 / 0 steps before attributing it to the emulation.

### C. Modulation and time variance (35 cases, 39 min): *the main target, part 2*
- **C1 impulse trains**, 24 impulses 12 s apart at Time 1.0 / 2.5 / 4.5, Noise on, plus Noise-off controls and a train with +1 sample drift per impulse. If the generator free-runs, each impulse sees a different modulation state, so the 24 are **24 independent snapshots of the same setting**: the capture-to-capture decorrelation curve per band (the `ml_structure.md` §4–5 metric), the depth against the Noise-off IR, and which part of the IR varies. If the 24 are identical the state restarts on onset, which is itself the finding. The Noise-off train tests **time invariance** including block phase.
- **C2 long tones**, 250 Hz / 1 kHz / 4 kHz, 60 s, Noise on and off (plus 1 kHz at Time 0.4 and 4.5). Complex demodulation of the reverb output gives phase (FM, delay modulation) versus amplitude (AM, gain modulation) sidebands: rate, depth, waveform (random, stepped or smooth), and whether depth grows with frequency as delay modulation must. The Noise-off twin is the control.
- **C3 onset shift**: the same impulse at 0 / 1 / 2 / 3 / 100 / 511 / 512 / 513 / 1000 samples, 0.5 / 1 / 2 / 3.7 s, each in a fresh instance, plus an exact-repeat control. Tells whether the random state is tied to stream time (and at what granularity: 1 sample, one block of 512, or the device clock) or to the instance.
- **C4 reset and toggle**: plugin reset between two impulses (does it re-seed), Noise switched off/on during a tone, Noise switched off mid-tail (does the modulation stop at once, hold, or ramp).
- **C5 repeated sweeps**, six ESS 8 s apart, Noise on and off: the sweep-pair calibration of `NEXT_STEPS.md` §10, for the detectors that run on library sweeps.
- Mapping to the 246: `EMT250_program.md` §8's open question is **which modulation the E uses** (the 250's LFSR address jitter, or the 246's stochastic control with M/L's 0.83 Hz / 0.15 rad rms rotation). The UAD answers the first half: what a modelled 250 looks like (fast jitter versus slow rotation, depth, per-loop or global). It does not settle which one the E uses; that still needs the 246-E AMPL pairs.

### D. Other programs, rate and routing (77 cases)
- **D_programs**: Chorus I–IV and Space (impulse train + 1 kHz tone, Noise on/off), the other 250 time-based programs with randomised delay; Delay at several L/R times, Echo, Phase and Predelay at **96 kHz**. The 5 ms delay step measured in 96 kHz samples against the stated step recovers the plugin's internal rate and whether delays are integer samples of an internal clock (the same method as the 246's 26,373.6 Hz).
- **D_rate**: the same impulse and white noise at 44.1 / 48 / 88.2 / 96 / 192 kHz, Noise on and off. Is the emulation rate-independent (an internal rate plus SRC, with its own filter) or run natively; sets latency, bandwidth, and whether Noise-state timing depends on host rate.
- **D_route**: Mix law (0 … 1 at WetSolo 0), WetSolo override, Outputs Rear/Front, L-only / R-only / both input (the input summing law and channel gain).

### F. Parameter changes while ringing (13 cases)
Automation lands on a sample: Time 4.5 → 0.4 / 0.4 → 4.5 / 4.5 → 2.5 mid-tail, LF and HF decay jumps, Predelay jumps under a 1 kHz tone (dry-only and wet), L delay 0 → 315 ms under a tone, a Mix ramp (zipper noise or smoothing), Power toggled mid-tail, Program switched mid-tail. These reveal how the feedback gains are applied (instant, ramped or recomputed), the **delay-change implementation** (a click, a crossfade or a pitch ramp = the interpolation quality, which is what the 250's address randomisation exercises), and state retention on bypass and program switch.

## 5. Limits (state these with any result)
- The UAD plugin is a **commercial emulation of the 250**, not the 246's E and not an oracle. Everything it says about modulation and non-linearity is a *prior* until the 246's own evidence agrees. Keep it labelled **H** for the 246 until then.
- **Licensing:** the captures are renders of a licensed plugin and stay local (`analysis/uad250/captures/` is gitignored); do not commit them or derived assets that could stand in for the plugin.
