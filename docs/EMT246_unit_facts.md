# EMT 246: consolidated unit facts

The single place for *what we know about how the unit works*. Details and evidence live in the linked docs; this sheet is updated whenever a finding changes.
- `discovery` = EMT246_discovery.md
- `research` = algorithm_research.md
- `model` = model_s_results.md
- `ml` = ml_structure.md

**Confidence:**
- **C** = confirmed by a primary source or a direct measurement;
- **S** = strong: several independent measurements agree;
- **H** = hypothesis.

Constraints: there is no hardware access, ROM dump or new capture, ever. Evidence comes from existing IRs, documents and photos only.

*Last consolidated: October 2026.*

---

**At a glance:** **mono in, stereo out** (C). A single balanced input; L and R outputs come from one multiplexed DAC, with L half a sample late. Each stereo IR is the complete 1-in/2-out response of a setting.

| **Delay addressing is in hardware: `address = Base Address Counter + Tap Offset Memory[tap number]`**. A 16-bit base counter (Z333–Z336) counts up every sample; a 16-bit adder (Z337–Z340) adds the offset from the TOM (Z331/Z332, buffered by Z329/Z330), which has its own **Tap Number Counter**. So every delay element is an **integer-sample tap of one 64 K-word circular memory**, and the tap offsets are loaded per setting. The two TOM chips are probably the two UM6116 2 K × 8 SRAMs seen in the photos (so up to 2 K tap entries, far above the time budget) | C (structure) / H (TOM = UM6116) | p. 53; SP self-test error list (Test 12) |

| **Processor B (sheet 3/5, p. 56, read October 2026):** TMS32010NL Z313 with instruction ROM B = **2 × AM27S191 (Z314 "BGC 6A", Z315 "BGC 5A") = 2 K × 16**; the sockets Z316/Z317 for a second 2 K are not mounted (JP304/JP305 set the chip selects). Its external data bus (Z358/Z359, "DIR B EXT") and the DLM B data/address buffers to J302 (Z363/Z364/Z367/Z368) are **all not mounted**, so B has **no path to the control CPU**. For the 0.83 Hz coupling rotation (`ml_structure.md` §9) this means A's code makes it, either itself or from values the Z80 sends; nothing on the board points to which | C (wiring) / H (consequence for θ) | p. 56 |
| **Processor A's port map (74S138 decode):** OUT 0 = write memory (MIR), 1 = load tap counter, 2 = load TOM, 3 = OUT FP (to the control CPU / panel via the external bus J301), 4 = to processor B, 5 = DAC 1 data, 6 = DAC 2 data; IN 0 = read memory (MOR), **1 = increment the base-address counter (IN BAZ)**, 2 = from B, 4/5 = front-panel data (FP1/FP2), 6 = A/D data. **The delay-line pointer is therefore advanced by the DSP program (one IN BAZ per sample), and the parameters arrive from the Z80 over the external bus**, which fits the step-to-coefficient tables living in the Z80 EPROM. Processor B has no external ports fitted (its decoders Z360/Z361 and J302 are "not mounted"): it talks to A and to memory only | C | p. 57 |
| **Interface board 7 246 125 (pp. 61–63, read October 2026):** a Z80A (PIO, CTC, EPROM 2764 "BGX 1A" = 8 KB, RAM 6116) receives the front panel's 32-bit packets (answering 8 bits in the pause) and MIDI. Towards the DSP it has **four 74LS374 latches loaded byte by byte from the Z80's 8-bit bus: Z507 + Z508 drive the 16 lines to processor A when EN FP1 is active, Z509 + Z510 when EN FP2 is**. So the Z80 hands A **two 16-bit words (FP1 / FP2, A's IN 4 / IN 5), a 32-bit mailbox the DSP polls**; full 16-bit words pass, so the path does not limit coefficients to 8 bits. | **Sample timing is a hardware sequencer:** an 8-bit timing counter (2 × 74LS193) clocked by CLKOUT A (about 208 ns) addresses a timing PROM (MMI 63S281, "BGD 1A") and a register that drive **DA enable 1/2, DA S&H 1/2, A/D S&H A/B, A/D clock (SAR) and BIO** (the DSP's sync input). | **L/R offset is a timing-ROM step:** the two D/A S&H pulses are placed by the PROM in 208.3 ns steps, so half a sample is 91 steps (18.96 µs). | **Input integrate/hold (input board sheet 2/3, p. 41; timing p. 39):** Z102 → R114 787 Ω → TL191 switches → LF356 integrator Z104 with C105 1 nF, and a feedback T (R116 1 k, C104 1 nF, R115 1 k) from its output, so it is a **leaky integrator, gain −2.54, critically damped with τ = 1 µs**. - 64 K words of delay RAM. Maximum pre-delay is 26,347 words, leaving **about 39 K words** for the loops, cluster and diffusion.
- S's loops use 5,758 words. M's recursion line is about 11.5 K words and L's about 23 K (§5b, **H** for the single-line form), both within the 39 K.
- 364 instructions per sample in total, i.e. about 50–70 weighted delay taps for the whole machine.

**Memory-access count for the identified S structure** (each delay element = one tap-offset entry per read or write; **H** for the access pattern, counted from §5):

| Part | Accesses per sample |
|---|---|
| Input write, pre-delay read | 2 |
| Reflection cluster (4 taps per channel, 2 channels) | 8 |
| 4 loops (1321/1389/1461/1587): one read and one write each | 8 |
| 460 comb: read and write | 2 |
| Diffuser AP20 · AP72 · AP230: read and write each | 6 |
| Read-outs (lags 26 and 332 in each of the 4 loops, shared by L and R) | 8 |
| **Identified total** | **about 34** |

The identified structure uses about 34 of the **256** tap-offset entries (§2b) and about half of the 50–70-tap instruction budget (a read, a multiply-accumulate and a write cost several of the 182 cycles per DSP). **The instruction budget, not the tap memory, is the binding limit.** What the 256 limit settles: the sparse injection fits (1,719 integer taps per channel) cannot be the real structure, and the unidentified injection and per-loop read-out must fit in about 20–35 accesses.

The budgets above are **H**, derived from the parts and TI timings; the 256 limit and the 64 K words are **C** (service manual).

## 7. Open questions (ranked)
